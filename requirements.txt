# Dependencies for the FiRE pipeline (src/) and baselines.
#
# Version pins are intentionally omitted below; pin them after installing
# and running the pipeline in your own environment, then freeze with:
#   pip freeze > requirements.lock.txt

requests
# Used for direct HTTP calls to model APIs (fire_stage2_3_single_model.py,
# fire_stage5.py, fire_worker2.py, fire_worker3_ace.py, and the baseline
# scripts all build request headers manually, e.g.
# "Authorization": "Bearer " + api_key).

openai
# Client for GPT-5.1 calls used throughout the pipeline (extraction,
# Worker 2's Oracle/Judge, Stage 5's rescue verifier) and by one of the
# three frontier-model baselines. See technical_appendix.pdf, Section 9
# ("Same-model discipline").

sentence-transformers
# all-MiniLM-L6-v2, used for semantic state-space matching and Stage 4's
# grounding check (technical_appendix.pdf, Sections 3.2 and 9.2). Pulls in
# torch as a dependency; the reported evaluation ran CPU-only.

python-dotenv
# For loading a local .env file into os.environ during development. All
# API keys are read via os.environ.get(...) rather than hardcoded; if your
# setup sources keys another way (shell profile, secrets manager), this
# package is not required.

# google-generativeai
# For Gemini 3.1 Pro baseline calls. Uncomment if the baseline harness
# uses the SDK directly rather than raw HTTP via `requests`.

# xAI/Grok client
# For the grok-4.20-0309-reasoning baseline. xAI's API is OpenAI-compatible,
# so the `openai` client (pointed at xAI's endpoint) or `requests` above
# may cover this without an additional package — check baselines/ for
# which path the harness actually uses.

# Setup note: API keys are read from environment variables, never
# hardcoded. Check the constant near the top of each src/ file
# (API_KEY_ENV, RESCUE_API_KEY_ENV, or the per-model key_env list in the
# baseline scripts) for the exact variable name each script expects.
